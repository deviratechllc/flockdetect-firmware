What's new in v3

  • Build badge on screen — the scan banner, every diagnostic page header and the options menu now show which build is running, so a photo or a bug report identifies itself.
  • Diagnostics pages (SEL → Diagnostics; SEL cycles pages, Up/Dn scrolls, ESC exits). Three views: a per-stage capture counter chain, the IE signatures actually computed from wildcard probes, and every source heard regardless of tier — plus an optional flockdiag_*.csv on SD.
  • No more screen strobing. The border and title are painted once instead of every frame, and the list no longer reshuffles between redraws.
  • Title collision fixed — the scan banner was drawing over the "FLOCKDETECT" header.
  • Animated UI — radar sweep with signal-scaled blips, eased RSSI bars, new-device highlight, and an expanding-ring alert.

Detection has been validated in the field against known Flock Safety cameras cross-referenced with DeFlock. The diagnostic pages are there so results can be checked rather than taken on trust.

Flash it manually

USB-C the board, then with esptool:

esptool.py --chip esp32s3 --baud 921600 write_flash 0x0 Bruce-lilygo-t-embed-cc1101-v3.bin

If the board doesn't enter download mode automatically, hold BOOT while tapping RESET, then run the command. Erase first with esptool.py --chip esp32s3 erase_flash if you're coming from very different firmware.

What it does

Passively identifies Flock Safety ALPR gear and related surveillance devices over WiFi and BLE, with a tiered alert model:

CONFIRMED → alarm + LED SUSPICIOUS → visual INFO → list only

  • WiFi (WiFi → FlockDetect): wildcard-probe IE-signature fingerprint, Flock-XXXXXX/test_flck SSID patterns, hidden-SSID flagging, and Flock / SoundThinking / camera-vendor OUI tables.
  • BLE (Bluetooth → FlockDetect BLE): Raven acoustic-sensor service UUIDs (+ firmware estimate), Flock-family device names, and the XUNTONG manufacturer ID.
  • Encoder-scrolled device list, full-screen alert takeover with buzzer + LED-ring flash, per-MAC anti-spam, and CSV logging to SD (optional GPS tagging).

Detection only — passive receive, no transmit. Signatures shift as vendors change hardware; treat SUSPICIOUS/INFO as leads to verify, not positive IDs.
